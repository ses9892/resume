소개.

세상에 완벽한 코드와 개발은 없다고 생각합니다. 수치 개선도 중요하지만, 장애가 났을 때 원인을 분석하고 해결 과정을 끌어내는 개발자가 잘하는 개발자라고 믿습니다.

금융권 실시간 중계 서버부터 AI Agent 백엔드까지 개발해 온 백엔드 개발자 장진호입니다. 우리은행·KB증권·농협 프로젝트에서 설계부터 Spring·Netty 서버 개발, 내부망 인프라 구성·운영까지 맡으며 장애는 로그로 원인 구간을 좁혀 근본 원인부터 고쳐 왔습니다. 지금은 LangChain·LangGraph 기반 Agent 백엔드를 개발하며 실무에서도 코딩 Agent를 적극 활용합니다. Agent가 만든 코드 역시 완벽하지 않기에, 요구사항·테스트·검증 보고를 거치는 개발 프로세스 안에서 쓰도록 Agent Skill을 팀에 도입해 코드 품질과 서비스 안정성을 높이고 있습니다.

일하는 방식.

  • 프로세스를 지키고, 테스트로 증명합니다

    요구사항을 문서로 합의하고 인터페이스를 정한 뒤, 실패하는 테스트로 기대 동작을 먼저 고정하고 구현합니다. 금융권에서는 ERD·인터페이스 정의서로 연동 규격부터 맞췄고, 지금은 요구사항 → 인터페이스 → 구현 플랜 → 검증 보고 순서를 따릅니다. 테스트는 개수보다 의미를 봅니다. 의미 없는 Mock 테스트는 걷어내고, 깨지면 안 되는 연동과 도구 계약을 테스트로 지킵니다.

  • 로그를 기능과 함께 설계합니다

    금융권 프로젝트에서 원청사·은행과 문제 구간을 가릴 때 근거는 결국 로그였습니다. 로그가 섞이던 녹취 시스템은 AOP로 인터페이스 수신 로그를 분류해 grep으로 바로 찾게 했고, 끊기던 중계 구간은 양방향 로그로 timeout 미처리 지점을 찾았습니다. 그래서 기능을 만들 때 장애가 나면 무엇으로 찾을지를 함께 정하고, 지금은 Agent 요청도 LangSmith trace와 Grafana·Loki로 추적합니다.

  • Agent를 적극적으로 쓰되, 프로세스는 지킵니다

    Codex·Cursor·Grok Build 같은 코딩 Agent를 매일 쓰지만, Agent에게도 사람과 같은 절차를 요구합니다. 요구사항 문서 없이 구현을 시작하지 않고, '테스트했다'는 말 대신 실행 로그를 완료 근거로 남기게 합니다. 이를 위해 TDD·플랜 작성·완료 전 검증 같은 Agent Skill을 팀 저장소에 도입하고, MCP 도구 호출·vCenter 운영처럼 사내 업무에 맞는 스킬은 직접 만들었습니다.

  • 혼자 잘 쓰는 것보다, 팀이 함께 쓰게 만듭니다

    Agent는 주어진 맥락만큼 일합니다. 그래서 아키텍처 문서·용어집·전역 지침을 정비해 누가 Agent를 쓰든 같은 맥락에서 작업하게 했고, 스킬과 바이브코딩 개발 방식을 팀원들과 공유하며 인사업무 AX처럼 개발 밖의 사내 업무로 넓히고 있습니다. 모호한 요구는 코드보다 대화로 먼저 풀고, 합의한 내용은 문서로 남깁니다.
