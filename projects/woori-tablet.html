트러블슈팅

01Zeus Reverse Proxy 웹뷰 렌더링 지연

문제

Reverse Proxy를 거치면서 웹뷰 화면의 브라우저 캐시 · 리소스 로딩이 매우 느려 렌더링이 지연됐습니다.

원인 파악

실제 태블릿 웹뷰로 재현하고, Zeus 로그로 리소스마다 몇 ms에 내려받아지는지 확인했습니다. 정적 리소스가 캐시되지 않고 요청마다 내부 WAS까지 다시 받아오고 있었습니다.

해결

Zeus 설정을 조정했습니다. 정적 리소스(JS · CSS · 이미지)에 캐시 헤더(Cache-Control · Expires)를 적용하고, 응답 압축과 Keep-Alive 연결 재사용을 켜서 반복 다운로드와 연결 비용을 줄였습니다.

결과

리소스 재다운로드가 사라져 웹뷰 화면 렌더링 지연을 해소했습니다.

02TCP Proxy 연결 끊김 — 녹취 단절 방지

문제

직접 구현한 TCP Proxy에서 idle timeout 등으로 연결이 비교적 자주 끊겨 녹취가 중단될 위험이 있었습니다.

원인 파악

앱 → Proxy, Proxy → 녹취 서버 양방향으로 로그를 남겨 비교하고, timeout 처리가 되지 않은 구간을 찾았습니다.

해결

timeout 미처리 구간을 보완하고, 연결이 끊겼을 때를 대비한 폴백 전략을 구축했습니다.

결과

연결이 끊기는 상황에서도 녹취가 끊기지 않도록 개선했습니다.

04

핵심성과

안정성 녹취 끊김 없는 TCP 중계

양방향 로그로 timeout 미처리 구간을 찾아 보완하고 폴백 전략을 더해, 연결이 끊겨도 녹취가 이어지게 만들었습니다.

성능 웹뷰 렌더링 지연 해소

Zeus 로그로 리소스별 다운로드 시간을 측정하고 캐시 · 압축 설정을 조정해, 리소스 재다운로드를 없앴습니다.

구축 외부망 태블릿 → 내부망 녹취 연결

중계망 TCP Proxy를 직접 구현해, 기존 녹취 인프라를 그대로 쓰면서 태블릿 녹취를 받을 수 있게 했습니다.
